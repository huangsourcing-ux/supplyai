## Frozen implementation behavior

- Cluster and factory Create return server-generated 21-character IDs and
  always begin as draft; factories also begin unverified.
- Create is intentionally image-free. After Create, the administrator requests
  a five-minute ADM-6 PUT URL for the returned entity ID, uploads directly to
  the public media bucket, and PATCHes the returned objectKey onto that entity.
- Object keys are generated by the API under the current environment prefix and
  exact entity path. Cross-environment, cross-kind, and cross-entity references
  are rejected before any database update.
- PATCH performs an authenticated R2 HEAD and accepts only an existing non-empty
  JPEG, PNG, or WebP object no larger than 10 MB. Public APIs return only the CDN
  URL; Admin responses also retain the objectKey needed for subsequent edits.
- Admin GET remains outside the write throttle. Create, PATCH, verify,
  publish/unpublish, and presign share the Redis-backed per-administrator write
  limit.

## Canonical staging prerequisite

Use an Owner-selected existing staging factory and an image whose source and
authorization are recorded. Do not upload a repository fixture or synthetic
image. The implementation PR must be merged and the exact main commit must pass
CI Gate, CMS migration, Core migration, Staging Release Gate, and Railway API
deployment before this checklist is executed.

Never record a Clerk token, R2 credential, complete presigned URL, or cookie in
this file or terminal output. The presigned URL is a bearer token until expiry.
